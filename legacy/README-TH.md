# 1DD Guide

เว็บสร้างคู่มือสำหรับลูกค้า พัฒนาด้วย HTML / CSS / JavaScript โดยไม่ต้อง build หรือใช้ framework ตัวเว็บวางบน Vercel หรือโฮสต์ 1DD ได้ ส่วนบัญชีผู้ใช้ ฐานข้อมูล และรูปภาพใช้ Supabase

## ไฟล์ในชุดนี้

- `index.html`, `styles.css`, `app.js` — หน้าสร้างและแก้ไขคู่มือ
- `core.js` — โมเดลโปรเจกต์และตรวจข้อมูลนำเข้า
- `templates.js` — เทมเพลตเริ่มต้น 6 แบบ เพิ่มหรือแก้หัวข้อเริ่มต้นในไฟล์นี้ได้
- `viewer.js` — สร้าง HTML คู่มือแบบอ่านอย่างเดียว พร้อมเลย์เอาต์พิมพ์ PDF
- `cloud.js`, `config.js` — เชื่อม Supabase Auth / Database / Storage
- `supabase/setup.sql` — ตาราง สิทธิ์ RLS และฟังก์ชันสำหรับคลาวด์
- `assets/` — โลโก้จริง 1DD, Google Sans ไทย/อังกฤษ และภาพตัวอย่างจากไฟล์ต้นฉบับ
- โฟลเดอร์ `1dd-capture-extension/` ใน repository นี้ — ส่วนขยาย Chrome สำหรับจับภาพแท็บหลังบ้านที่ล็อกอินแล้ว

ฟอนต์และรูปที่ส่งออกฝังใน HTML ลูกค้า จึงเปิดอ่านออฟไลน์ได้ ฟอนต์ Google Sans อยู่ภายใต้ SIL Open Font License ดู `assets/GOOGLE-SANS-LICENSE.txt`

## เปิดทดลองบนเครื่อง

จากโฟลเดอร์ `1dd-guide-studio` รัน:

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

เปิด `http://localhost:4173/` ผ่านเบราว์เซอร์ ข้อมูลทดลองบันทึกใน IndexedDB ของเบราว์เซอร์นั้น ก่อนย้าย URL / เครื่อง / เบราว์เซอร์ ให้เปิด **เพิ่มเติม → สำรองข้อมูลทั้งหมด** เป็น JSON แล้วนำเข้าในปลายทาง ไม่แนะนำเปิดตัวแก้ไขผ่าน `file://`

เมื่อยังไม่ตั้งค่า Supabase สถานะมุมบนจะแสดง “บันทึกแล้วในเครื่องนี้” เมนูคลาวด์ สำรองข้อมูล และตั้งค่าอยู่ใน “เพิ่มเติม” ด้านล่างแถบซ้าย

## วางบน Vercel

ชุด repository นี้มี `index.html` อยู่ระดับบนสุด พร้อม `preview.html` สำหรับเปิดตัวอย่างแบบลูกค้า และ `preview.pdf` สำหรับดูตัวอย่างพิมพ์ ใช้โฟลเดอร์นี้เป็น root ของ repository และของ Vercel ชุดนี้ไม่มีข้อมูลโปรเจกต์จาก IndexedDB ของผู้ใช้

เมื่อย้ายจาก localhost ไปโดเมน Vercel ให้ **เพิ่มเติม → สำรองข้อมูลทั้งหมด** ในเว็บเดิม แล้ว **นำเข้าไฟล์สำรอง** ในเว็บใหม่ เพื่อย้ายโปรเจกต์เดิม หากยังไม่เชื่อม Supabase ข้อมูลยังบันทึกในเบราว์เซอร์ของเครื่องนั้น

1. อัปโหลดไฟล์และโฟลเดอร์ทั้งหมดในชุดนี้ไว้ระดับบนสุดของ repository แล้ว Import Project บน Vercel
2. เลือก Root Directory ให้ตรงโฟลเดอร์ที่มี `index.html`
3. Framework Preset: **Other**, Build Command และ Install Command: เว้นว่าง, Output Directory: `.`
4. ใช้ `vercel.json` ที่แนบมา แล้ว Deploy
5. ตั้งค่า Supabase ตามหัวข้อถัดไป และ deploy `config.js` ที่กรอกค่าจริงแล้วอีกครั้ง

เว็บนี้ใช้ hash routing จึงไม่ต้องตั้ง catch-all rewrite อ้างอิง [Vercel: Configuring a Build](https://vercel.com/docs/builds/configure-a-build)

## วางบนโฮสต์ 1DD

อัปโหลดเนื้อหาทั้งโฟลเดอร์ `1dd-guide-studio` ลงโฟลเดอร์เว็บ เช่น `public_html/guide/` แล้วเปิด `https://โดเมนของคุณ/guide/` ใช้ HTTPS สำหรับการจับภาพและ clipboard ไม่ต้องใช้ PHP หรือ Node.js บนโฮสต์ แต่ต้องเชื่อม Supabase สำหรับการทำงานบนคลาวด์

## เปิดใช้คลาวด์ครั้งแรก

1. สร้าง Supabase project ของทีม 1DD
2. เปิด SQL Editor วางและรัน `supabase/setup.sql` ทั้งไฟล์ สคริปต์สร้างตาราง `guide_*` และ bucket ส่วนตัว `guide-images` พร้อมสิทธิ์เข้าถึง
3. เปิด Email authentication และการยืนยันอีเมล
4. ใน Authentication → URL Configuration ตั้ง **Site URL** และ **Redirect URLs** เป็น URL จริงของ Guide รวม path และ `/` ท้าย URL เช่น `https://guide.example.com/` หรือ `https://example.com/guide/` ตาม [เอกสาร Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls)
5. ตั้ง custom SMTP ก่อนให้ทีมทั่วไปสมัคร ระบบส่งอีเมลเริ่มต้นของ Supabase มีข้อจำกัดผู้รับและอัตราส่ง ดู [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp)
6. ใส่ Project URL และ **publishable key** หรือ legacy **anon key** ใน `config.js`:

```js
window.GUIDE_CONFIG = {
  supabaseUrl: 'https://YOUR-PROJECT.supabase.co',
  supabaseKey: 'sb_publishable_YOUR-KEY'
};
```

ค่าเหล่านี้เป็น public configuration ที่ใช้ร่วมกับ RLS ห้ามใส่ `service_role`, `sb_secret_` หรือรหัสผ่านฐานข้อมูลในเว็บ

7. อัปโหลด `config.js` ไปยังโฮสต์แล้วโหลดหน้าใหม่ หรือกรอกค่าผ่านเมนู **เชื่อมคลาวด์** แล้วดาวน์โหลด config.js จากแอปไปแทนบนโฮสต์
8. สมัครบัญชี ยืนยันอีเมล เข้าสู่ระบบ และสร้าง Workspace
9. หากมีงานบนเครื่องอยู่แล้ว ให้สำรอง JSON ก่อนเข้า Workspace แล้วนำเข้า JSON นั้นใน Workspace ข้อมูลบนเครื่องไม่ถูกย้ายอัตโนมัติ

ยังไม่มี Supabase project จริงเชื่อมในไฟล์ที่ส่งมอบ จึงต้องตั้งค่าและตรวจการเข้าสู่ระบบ/สิทธิ์บนบริการจริงก่อนใช้กับทีม

## ทำงานกับทีมและแยกลูกค้า

เจ้าของ Workspace เพิ่มอีเมลผู้แก้ไขได้ที่ **คลาวด์ / ทีม → สมาชิก** จากนั้นส่ง URL ของ Guide ให้สมาชิกเอง ระบบนี้ไม่ส่งอีเมลเชิญอัตโนมัติ สมาชิกต้องสมัครและยืนยันอีเมลให้ตรงกับที่เชิญ

ผู้แก้ไขเห็นและแก้ไขทุกโปรเจกต์ใน Workspace นั้น ลูกค้าควรรับ HTML/PDF หรือ **ลิงก์คู่มือเฉพาะโปรเจกต์** แทนบัญชีผู้แก้ไข ถ้าทีมที่แก้ไขแต่ละลูกค้าต้องแยกสิทธิ์ ให้ใช้คนละ Workspace

รุ่นนี้ใช้การบันทึกพร้อมตรวจ revision เมื่อสองคนแก้ไขพร้อมกัน ระบบหยุดการบันทึกของคนที่ถือข้อมูลเก่า พร้อมให้สำรองงานและโหลดล่าสุด ไม่มีการรวมการแก้ไขพร้อมกันแบบ Google Docs

## หลายภาพในเนื้อหาเดียว

กด **เพิ่มภาพ** เหนือพื้นที่ภาพ แล้วเลือก **อัปโหลดภาพ** หรือ **จับภาพหน้าจอ / หน้าต่าง** การอัปโหลดเลือกไฟล์เดียวหรือหลายไฟล์พร้อมกันได้ สูงสุด 20 ภาพต่อเนื้อหา ทุกภาพแสดงเรียงต่อกันด้านล่าง คลิกภาพย่อด้านบนเพื่อเลื่อนไปยังภาพนั้น หมายเลขและคำอธิบายเก็บแยกกันต่อภาพ

พิมพ์แก้ชื่อในแถบภาพได้โดยตรง กด Enter หรือคลิกออกเพื่อบันทึก และกด Esc เพื่อยกเลิก ชื่อที่ตั้งจะแสดงในหัวข้อภาพ มุมมองลูกค้า HTML และ PDF ด้วย

มุมมองลูกค้าและ HTML ที่ส่งออกมีแท็บภาพย่อพร้อมชื่อ กดเพื่อเลื่อนไปยังภาพนั้น ทุกภาพแสดงเรียงลงมาตามลำดับ คำอธิบาย Point อยู่ทางขวาบนหน้าจอกว้าง และอยู่ใต้ภาพบนหน้าจอแคบ ส่วน PDF เริ่มแต่ละภาพบนหน้าใหม่และพิมพ์ครบทุกภาพของเนื้อหาที่เลือก สามารถลบภาพที่เลือกผ่าน **เปลี่ยนภาพ → ลบภาพและหมายเลข** ได้

ไฟล์สำรองรุ่น 2 เก็บภาพเพิ่มเติมด้วย และยังนำเข้าไฟล์รุ่น 1 ได้ ข้อมูลบนเครื่องเดิมเปิดต่อได้โดยไม่ต้องนำเข้าใหม่ หากใช้คลาวด์อยู่แล้ว ให้รัน `supabase/setup.sql` รุ่นล่าสุดอีกครั้งเพื่อให้เผยแพร่ไฟล์รุ่น 2 ได้ สคริปต์ไม่ล้าง Workspace เดิม

## สร้างคู่มือ

1. กดสร้างโปรเจกต์ เลือกเทมเพลต ใส่ชื่อลูกค้า ส่วนเว็บไซต์เว้นว่างได้ หรือใส่โดเมนสั้น ๆ เช่น `1dd.co` โดยไม่ต้องใส่ `https://` ระบบเติมให้เมื่อนำไปสร้างลิงก์
2. อัปโหลดโลโก้ลูกค้า SVG/PNG หรือพิมพ์ข้อความแทนโลโก้ได้ในฟอร์มสร้างโปรเจกต์ จากนั้นเพิ่มเนื้อหาสำหรับแต่ละหน้า ใส่ชื่อ คำเกริ่น และ URL หลังบ้าน
3. เพิ่มภาพด้วยอัปโหลด / วางภาพ / จับภาพหน้าจอหรือหน้าต่าง
4. เลือก **ปักหมายเลข** แล้วคลิกตำแหน่งบนภาพ เขียนหัวข้อและคำอธิบายทางขวา
5. ลากจุดเพื่อย้าย ใช้ปุ่มขึ้น/ลงจัดลำดับ ใช้ **ปิดทับ** สำหรับข้อมูลที่ไม่ต้องการแสดง การปิดทับถูกเขียนลงภาพจริง
6. กด **ดูแบบลูกค้า** เพื่อตรวจ แล้ว **ส่งออกคู่มือ**

การใส่ URL ของหน้าที่ต้องล็อกอินอย่างเดียวไม่สามารถดึงภาพจาก session ของอีกเว็บไซต์อัตโนมัติได้ รุ่นนี้ใช้ภาพจากแท็บที่คุณล็อกอินไว้ด้วยตัวเอง การจับภาพในเว็บจะมีหน้าต่างให้เลือกแท็บ/หน้าจอทุกครั้ง และจับเฉพาะส่วนที่มองเห็น หากต้องการภาพยาวให้ใช้ไฟล์ screenshot แบบเต็มหน้าที่ถ่ายไว้แล้ว

## เทมเพลตและการแก้ไขชื่อ

- **New project**: โปรเจกต์ว่าง ไม่มีเนื้อหาเริ่มต้น
- **Corporate**: 5 เนื้อหา — เข้าสู่ระบบ หน้าเว็บไซต์ รูปและไฟล์ บทความ และเมนู
- **WooCommerce**: 6 เนื้อหา — เข้าสู่ระบบ สินค้า รูปสินค้า หมวดหมู่ ราคา/สต็อก และออเดอร์
- **Shopify**: 6 เนื้อหา — เข้าสู่ระบบ สินค้า Collections ออเดอร์ หน้าเว็บไซต์ และหน้าแรก
- **Product Catalog**: 5 เนื้อหา อ้างอิงเมนูสินค้า WordPress + WooCommerce
- **Article**: 5 เนื้อหา — เข้าสู่ระบบ บทความ หมวดหมู่ รูป/ไฟล์ และฉบับร่าง/ตั้งเวลา

แต่ละเทมเพลตสร้างหัวข้อ พร้อม Point 1–3 ในแถบคำอธิบายด้านขวา แก้หัวข้อและข้อความได้ทันที แยกข้อมูลกันทุกโปรเจกต์ Point ยังไม่มีตำแหน่งจนกว่าจะเพิ่มภาพแล้วกด **วางจุดบนภาพ** หรือเลือก **ปักหมายเลข** แล้วคลิกวางทีละจุด การเพิ่มภาพครั้งแรกเก็บข้อความ Point เดิมทั้งหมด การเปลี่ยนภาพภายหลังคงข้อความไว้ แต่ให้วางตำแหน่งใหม่ WordPress เติม URL หลังบ้านจากเว็บไซต์ที่กรอก รวมถึงการติดตั้งในโฟลเดอร์ย่อย ส่วน Shopify เปิด admin กลาง ให้เลือกร้านและเปลี่ยนลิงก์แต่ละหน้าเอง ชื่อเมนูจริงอาจต่างกันตามธีม ปลั๊กอิน และสิทธิ์บัญชี

คลิกชื่อบนการ์ดโปรเจกต์หรือใน Sidebar แล้วพิมพ์ใหม่ กด Enter หรือคลิกออกเพื่อบันทึก กด Esc เพื่อยกเลิก ชื่อว่างจะคืนค่าเดิม ส่วน URL ใต้ชื่อบนการ์ดก็แก้ได้แบบเดียวกัน พิมพ์โดเมนอย่าง `example.com` แล้วระบบเติม `https://` ให้ URL ที่ไม่ถูกต้องจะไม่ถูกบันทึก และการเปลี่ยนเว็บไซต์โปรเจกต์ไม่เปลี่ยน URL ของเนื้อหาแต่ละหน้าโดยอัตโนมัติ

หัวข้อเทมเพลตอ้างอิง [WordPress Administration Screens](https://wordpress.org/documentation/article/administration-screens/), [WooCommerce Orders](https://woocommerce.com/document/managing-orders/), [Shopify Products](https://help.shopify.com/en/manual/products/add-update-products) และ [Shopify Pages](https://help.shopify.com/en/manual/online-store/add-edit-pages) โดยเขียนคำแนะนำภาษาไทยแบบกลางให้ปรับตามเว็บไซต์จริง

## กรอบไฮไลท์และตัวอักษร

เลือก **กรอบไฮไลท์** แล้วลากบนภาพเพื่อสร้างกรอบเส้นทึบสีส้ม `#FF6600` หนา 2px ไม่มีเส้นประ เลือก **เลือก** เพื่อลากกรอบย้ายตำแหน่ง หรือใช้ปุ่มลูกศร เมื่อต้องการลบให้กด Delete/Backspace ขณะโฟกัสกรอบ หรือปุ่ม **ลบกรอบที่เลือก** และกดปุ่มย้อนกลับเพื่อคืนกรอบได้ กรอบเก็บแยกต่อภาพ และอยู่ใน HTML, PDF และไฟล์สำรอง รวมถึงการบันทึกคลาวด์

Sidebar ฝั่งจัดการใช้พื้นเทาอ่อน `#F3F4F6` ตัดกับพื้นที่ทำงานสีขาว ส่วน Sidebar แบบลูกค้ายังคงพื้นขาว ตัวอักษรเทา เมนูที่เลือกหรือชี้เมาส์มีพื้นส้มอ่อน `#FDF4ED` กับตัวอักษรและไอคอนสีส้มโลโก้ `#FF6600` ปุ่มเพิ่มเนื้อหามีกรอบเส้นประ จุดและกรอบบนภาพใช้สีส้ม 1DD หัวข้อขั้นตอนขนาด 16px ข้อความเนื้อหาและคำอธิบาย 14px สีดำ 80% และข้อความแนะนำใต้ภาพ 12px บนหน้าจอ (PDF ใช้ขนาดสำหรับการพิมพ์)

## ส่วนขยายจับภาพ Chrome

1. เปิด `chrome://extensions` เปิด Developer mode → Load unpacked → เลือกโฟลเดอร์ `1dd-capture-extension`
2. ใน Guide เปิดเมนู **เพิ่มเติม → ส่วนขยายจับภาพ** เพื่อดู URL และรหัสเชื่อมต่อ (นำตัวเลือกส่วนขยายออกจากเมนูบนภาพแล้ว)
3. กรอกสองค่านี้ในส่วนขยาย และอนุญาตเฉพาะเว็บไซต์ Guide ของคุณ
4. เปิดแท็บ WordPress ที่ล็อกอินแล้ว กด **จับภาพส่งเข้า 1DD**
5. กลับ Guide ตรวจภาพและเนื้อหาปลายทาง แล้วกด **ใช้ภาพนี้**

ส่วนขยายไม่อ่านรหัสผ่านหรือ cookies และไม่จับภาพเบื้องหลัง รองรับ Chrome/เบราว์เซอร์ Chromium ที่รองรับ Manifest V3 ยังไม่ได้ติดตั้งทดสอบกับ Chrome ของผู้ใช้ในรอบส่งมอบนี้

## โลโก้ลูกค้าและหน้าปก PDF

ใน **สร้างโปรเจกต์** อัปโหลดโลโก้ SVG หรือ PNG ขนาดไม่เกิน 5 MB ได้ พร้อมดูตัวอย่างก่อนบันทึก หากไม่มีรูป ให้กรอก **ข้อความแทนโลโก้** ถ้าเว้นทั้งสองช่อง ระบบใช้ชื่อโปรเจกต์แทน โปรเจกต์เดิมเปลี่ยนหรือลบโลโก้ได้ใน **ตั้งค่าโปรเจกต์**

ระบบวางโลโก้ในพื้นที่ **100 × 100px** โดยรักษาสัดส่วน ชิดซ้ายแนวเดียวกับโลโก้ 1DD และอยู่เหนือหัวข้อ **CONTENT UPLOAD / TUTORIAL** บนหน้าปก หน้าปกใช้เลย์เอาต์จากไฟล์อ้างอิง A4 - Cover.pdf กด **ดูแบบลูกค้า → ดูหน้าปก PDF** เพื่อตรวจก่อนพิมพ์

ไฟล์ SVG/PNG จะถูกแปลงเป็น PNG โปร่งใส 600 × 600px เพื่อให้ติดไปกับ HTML, PDF และไฟล์สำรองได้ครบ โลโก้และข้อความเก็บแยกต่อโปรเจกต์ และรองรับการบันทึกในคลาวด์เมื่อเชื่อม Supabase แล้ว

## HTML / PDF / แชร์ลิงก์

- **HTML:** ไฟล์เดียวต่อโปรเจกต์ มีภาพ ฟอนต์ โลโก้ สารบัญ แท็บภาพย่อ และไอคอนขยายภาพ เปิดออฟไลน์หรือวางบนโฮสต์ได้
- **PDF:** เปิดแบบลูกค้า เลือกทั้งโปรเจกต์หรือเนื้อหานี้ → ดาวน์โหลด PDF → เลือก Save as PDF ในหน้าพิมพ์ ระบบกำหนดขนาด **A4 แนวนอน** และใส่หน้าปกอัตโนมัติ ให้ปิด Headers/Footers ของเบราว์เซอร์และใช้ Scale 100% ภาพอยู่ซ้ายและคำอธิบาย Point อยู่ขวา แต่ละภาพเริ่มหน้าใหม่ ภาพยาวแบ่งเป็นช่วงพร้อมคำอธิบายที่ตรงกัน เลือกพิมพ์เฉพาะเนื้อหาก็มีหน้าปกนำหน้าเสมอ
- **JSON:** ไฟล์สำรองที่นำกลับมาแก้ไขได้ การนำเข้าจะสร้างสำเนาพร้อม ID ใหม่
- **ลิงก์คลาวด์:** เมื่อ deploy config.js แล้ว กดเผยแพร่จากโปรเจกต์ที่อยู่ในคลาวด์ ลิงก์เป็นแบบผู้ที่มีลิงก์เปิดอ่านได้ เผยแพร่เฉพาะ snapshot ของโปรเจกต์ที่เลือก การแก้ร่างจะไม่เปลี่ยนลิงก์จนกดอัปเดตเผยแพร่ มีปุ่มเพิกถอนลิงก์ แต่เพิกถอนไฟล์ที่ดาวน์โหลดแล้วไม่ได้

## ขอบเขตรุ่นแรกและการดูแล

ภาพรองรับ PNG/JPEG/WebP สูงสุด 12 MB ต่อภาพ และขนาดไม่เกิน 40 ล้านพิกเซล ลิงก์เผยแพร่จำกัด snapshot 28 MB รวมภาพที่เข้ารหัส หากเกินให้ลดขนาดภาพหรือแยกคู่มือ โปรเจกต์เก็บ metadata ในฐานข้อมูลและภาพใน Storage โดยแยกตาม Workspace

การลบ/เปลี่ยนภาพยังไม่ล้างไฟล์เก่าออกจาก Storage อัตโนมัติ เพื่อไม่ให้ไฟล์ที่โปรเจกต์อื่นใช้เสียหาย ควรติดตามพื้นที่และสำรองฐานข้อมูลกับ Storage ตามรอบของทีม

ก่อนเปิดใช้คลาวด์จริง ทดสอบด้วยสองบัญชี: คนที่ไม่ใช่สมาชิกต้องอ่าน Workspace/รูปไม่ได้, สมาชิกต้องอ่านและบันทึกได้, การแก้ชนกันต้องแจ้ง conflict, ลิงก์ลูกค้าต้องมีเพียงโปรเจกต์ที่เผยแพร่ และเมื่อเพิกถอนต้องเปิดไม่ได้ ทดสอบอีกเครื่องด้วย URL โฮสต์จริงเพื่อยืนยัน config และอีเมล
